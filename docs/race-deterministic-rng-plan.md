# Race fairness and deterministic RNG plan

## 目标

在 Race 模式中锁定指定世界，并为影响路线和收益的随机结果提供共享、可复现的随机源，同时保留原版条件、概率倍率、玩家幸运值和物品规则。

首版只支持已验证的 Terraria 1.4.5.6 x86 客户端。相同 Race 包、相同世界状态和相同受控操作应得到相同结果；玩家行为导致的世界状态差异仍可合法产生不同结果。

本功能提供正常 Race 流程中的公平性，不是反作弊系统。世界锁只限制游戏内的正常选择流程，不检测外部存档修改、内存编辑或定制客户端。普通单人模式和未启用该 Race 策略的游戏不受影响。

## 已验证基础

- Terraria 1.4.5.6 为 x86、`.NET Framework 4 Client Profile`、纯 IL 程序集。
- 已通过 x86 原生引导器把 net40 载荷加载进 Terraria 默认 AppDomain。
- 已按版本、MVID、方法签名和 IL SHA-256 定位 NPC 物品、Boss 补给、钱币和回血掉落方法。
- 正式载荷使用命名管道握手、摘要回读和心跳；退出 Race 时卸载 Harmony Hook。
- 载荷从独立临时目录加载，不锁定程序目录；发布包包含兼容性清单与 Harmony 许可证。

## 当前进度

## 确定性模型

### Race 随机包

服务器为每个 Race 包生成一次共享配置：

```text
DeterminismProtocolVersion
DeterminismEpochId
EntropySeed (256 bit)
TerrariaCompatibilityId
EnabledCapabilities
ChancePolicyVersion
```

所有参赛者接收完全相同的值。种子不使用客户端本地 `RunId`，也不直接复用世界种子。

当前确定性协议版本为 `5`，`ChancePolicyVersion` 为 `3`；顶层 NPC 掉落规则和幸运掷骰使用相互隔离的随机流。版本 5 同时定义房主统一开始、倒计时和完整重新开始流程。程序只接受当前版本，不保留旧协议兼容分支。

每个随机域通过 HMAC-SHA-256 派生独立种子：

```text
domainSeed = HMAC-SHA256(EntropySeed, protocolVersion | domainId | eventKey)
```

某一功能多消费或少消费随机数不得改变其他功能。

### 事件键

| 类型 | 事件键 | 用途 |
| --- | --- | --- |
| 坐标事件 | 世界哈希、方块坐标、方块类型、该坐标操作次数 | 摇树、罐子、钱币堆和普通方块掉落 |
| 顺序事件 | 来源类型、该来源的第 N 次操作 | Boss 掉落、开包、工具修饰语、随机传送 |
| 世界转阶段 | 世界哈希、阶段 ID、阶段次数 | 困难模式 V、祭坛矿物、月柱位置 |
| 独立概率掷骰 | 世界、物品、材料和第 N 次有效检查 | 炼药桌和微光材料检查 |
| 概率累加器 | 稳定 Chance ID、玩家或世界作用域 | 幸运触发 |
| 固定周期 | 进入 Race 世界后的游戏更新 tick | 城镇 NPC 检查 |

坐标事件按坐标分别计数，避免玩家仅因探索顺序不同而改变其他坐标的结果。全局进度事件仍按原版全局次数计数，例如第 N 个暗影珠和第 N 次敲祭坛。

### 作用域 RNG

同步主线程入口采用栈式作用域：保存 `Main.rand`，安装该事件的 `UnifiedRandom`，执行原版代码，并在 `finally` 中恢复原对象。嵌套功能使用子域，退出后恢复父域随机流。

困难模式转换运行在后台线程，不允许跨线程全局替换 `Main.rand`。该阶段必须使用线程局部上下文，并通过受控 getter 或 IL 转换把目标调用导向当前域 RNG。

特效、声音和绘制随机数不进入游戏结果域。高层方法若混合了结果与特效，必须转换精确调用点，不能粗略包住整个方法。

### 独立概率掷骰

炼药桌和微光的每份有效材料检查使用世界、物品、材料和检查序号组成事件键，通过共享种子派生无偏 `1/3` 掷骰。相同 Race 包和操作序列得到相同结果，但允许连续成功或连续失败，不提供固定次数保底。

### 概率累加器

需要平滑处理的受控幸运概率点分配稳定 `ChanceId`。累加器只在原版条件允许执行该次概率检查时前进：

```text
phase += numerator
if phase >= denominator:
    phase -= denominator
    success
```

- 初始 `phase` 由共享种子派生，避免所有 `1/N` 事件都固定在第 N 次首次发生。
- 使用整数有理数或等价的无漂移表示；`1/300` 在 300 个有效检查中恰好发生一次。
- 概率随状态变化时按新分母等比例保留进度，不因切换环境清空积累。
- 无效 tick、NPC 上限已满、事件互斥等情况不积累。
- 均匀选择“结果是什么”仍使用确定性随机流；累加器只替换“本次是否发生”。

原版幸运值保持有效。`Luck.RollLuck` 系列中由正负幸运决定是否进入额外掷骰的概率门改用累加器，之后的原版取最优或最差结果逻辑保持不变。Chance ID 由受支持调用点的方法 token 和 IL offset 生成，不使用运行时堆栈猜测。

普通刷怪的概率、环境倍率和时间分布全部保持原版。星尘柱只控制敌怪类型选择序列，不改变四柱区域或普通区域的刷怪时间。

## 运行时架构

- `Race.Contracts`：增加随机包、能力列表、兼容性状态和握手摘要。
- `Race.Server`：在 Race 包发布时生成共享随机包并随 Package Revision 固定。
- `Race.Client`：接收并校验随机包，协调 Terraria 进程和 Hook 握手。
- `Terraria` / `Infrastructure.Windows`：负责 x86 加载器、IPC、进程生命周期和兼容性检查。
- 独立 net40 x86 载荷：拥有 Hook、世界守卫、域状态、计数器和累加器，不依赖 WinForms。
- `WinForms`：只显示启用状态、兼容性和失败原因；不承载 Hook 逻辑。

发布包需要包含原生引导器、x86 注入器、net40 载荷、Harmony、许可证和兼容性清单。自动更新清单同步托管这些文件。

Hook 与 TerrariaSplit 使用命名管道握手。进入 Ready 前必须验证：

- Terraria exe SHA-256、程序集版本和 MVID；
- 所有启用能力所需方法的签名和 IL 指纹；
- Hook 协议版本、Harmony 版本和载荷版本；
- 当前随机包和能力集合；
- 目标世界已经在客户端绑定；
- Terraria 进程仍存活且 Hook 心跳有效。

任一检查失败时禁止 Ready，不允许静默回退成部分确定性。首版不支持 Race 过程中重启 Terraria；重启后必须重置本次 run，避免计数器和累加器回退。

### 世界绑定

Race 准备流程记录本次下载或生成的 Race 世界路径、`WorldId` 和 `UniqueId`，三者共同作为本次 run 的目标世界身份。

锁定从准备完成持续到本次 run 通关。期间允许退回主菜单后重新进入同一世界；选择其他世界或尝试加入服务器时只显示提示并拒绝本次加载。通关或主动放弃后解除限制。

该限制不约束角色，也不维护存档哈希链或检测文件覆盖、回滚和外部修改。

## 分阶段实施

### 阶段 0：生产化加载与随机域基础

工作：

- 将临时原型拆成正式 x86 引导器、注入器和 net40 载荷项目。
- 增加版本清单、IL 指纹检查、IPC 握手、心跳和卸载流程。
- 实现 HMAC 派生、域栈、事件计数器、整数累加器和诊断快照。
- Race Server 生成随机包；客户端不得自行补种子。
- 增加能力协商，服务器要求所有玩家能力集合完全一致。

验收：

- 连续启动、加载、安装空 Hook、卸载 100 次无残留和崩溃。
- 不受支持版本明确拒绝 Ready。
- 任意 Hook 异常都恢复 `Main.rand` 并使 Race 状态失败关闭。
- 非 Race 启动不加载任何载荷。

### 阶段 1：Race 世界锁定

工作：

- 从现有 Race 世界准备流程取得路径、`WorldId` 和 `UniqueId`，保存在客户端运行状态中。
- 在 `WorldGen.playWorld` 及其他本地世界加载入口检查目标，只允许加载已绑定 Race 世界。
- Race 锁定期间拒绝 Join Game；Host & Play 也必须选择已绑定 Race 世界。
- UI 显示当前绑定的世界和拒绝原因；锁定状态通过现有 Hook 握手传给客户端。
- 本次 run 完成或主动放弃时清除绑定，不持久化到下一场 Race。

验收：

- 指定世界可以正常开始；退回菜单后仍可重新进入同一世界。
- 其他本地世界和 Join Game 均在加载前被拒绝；Host & Play 只有选择指定世界时才允许继续。
- 正常自动保存和退出保存不受影响；通关或放弃后其他世界恢复可用。

### 阶段 2：NPC 与 Boss 直接掉落

工作：

- 分别 Hook `NPC.NPCLoot_DropItems(Player)`、Boss 药水与红心、钱币、普通回血掉落方法。
- 每类以规范化 NPC 掉落组和该组在本类别中的第 N 次结算作为事件键；各类别不会互相推进随机序列。
- 原版标记为 Boss 的最终掉落实例按规范化 Boss 组计数；普通部件按具体 NPC 类型独立计数，不能推进主体或共同掉落次数。
- 原版 `DropAttemptInfo.rng`、`Player.RollLuck`、专家/大师条件和掉落规则原样执行。
- 钱币随机倍率、普通回血、Boss 药水与红心数量均已覆盖；Boss 药水和 Boss 红心沿用原版同一补给方法，宝藏袋内容仍由玩家主动开启域负责。

验收：

- 两个干净进程使用同一随机包重复击杀，直接掉落逐项一致。
- 正幸运、零幸运和负幸运均可复现，且幸运仍改变结果分布。
- 在一个客户端执行无关随机操作，不改变另一个 NPC 掉落组的序列。

### 阶段 3：玩家主动触发的结果

| 功能 | 原版入口 | 确定性策略 |
| --- | --- | --- |
| 摇树掉落 | `WorldGen.ShakeTree` | 树底坐标、树类型和该树摇动次数；覆盖物品、NPC 和投射物结果 |
| 罐子、钱币堆、普通方块 | `WorldGen.KillTile` 的掉落分支 | 方块坐标、类型、frame 和该坐标破坏次数 |
| 暗影珠/猩红之心 | 特殊 `KillTile` 进度分支 | 邪恶类型和全局第 N 次破坏；保留第三次 Boss 规则 |
| 蠕虫罐、草药袋 | `Player.OpenCanofWorms`、`OpenHerbBag` | 来源物品类型和第 N 次开启 |
| 宝藏袋和板条箱 | `Player.OpenBossBag`、`OpenFishingCrate` | 包类型或箱类型和第 N 次开启 |
| 随机传送药水 | `Player.TeleportationPotion` | 玩家作用域第 N 次使用；原版最多 1000 次候选验证保持不变 |
| 工具修饰语 | `Item.Prefix` 及重铸入口 | 来源、工具类型和第 N 次掷前缀；继续执行原版前缀权重与合法性检查 |

世界文件中已经存在的工具前缀不重滚。初始范围包含掉落、开包、制作和哥布林重铸产生的工具修饰语；工具分类使用原版可掷前缀类别，不维护物品名白名单。

验收：

- 相同坐标的树或罐子在不同探索顺序下结果一致。
- 开其他类型的包不会移动目标包的序列。
- 随机传送在相同世界状态下坐标一致；目标被玩家修改为非法位置后允许选择下一个候选。
- 前缀合法性、重铸价格和顶级前缀提示保持原版行为。

### 阶段 4：炼药、微光和幸运概率控制

工作：

- 在 `Recipe.GetIngredientCraftingDiscount` 中把炼药桌每个材料的 `1/3` 节省检查改为共享种子驱动的独立确定性掷骰。
- 在 `WorldItem.GetShimmered` 的 alchemy 拆解分支中把每个材料的 `1/3` 扣减检查改为同算法的独立拆解域。
- 保留制作和拆解原版配方、数量、配方组以及微光解锁条件。
- 为 `Luck.RollLuck`、`RollBadLuck` 及其变体建立调用点清单，先覆盖已受控功能，再扩展全部游戏结果调用点。
- 增加 IL 扫描器；Terraria 更新后如出现未分类幸运调用点，兼容性检查失败而不是遗漏。

验收：

- 相同 Race 包和操作序列得到相同结果；不同材料检查相互隔离，并允许出现原版风格的连续成功或连续失败。
- 大量独立 `1/3` 检查的频率接近原版概率，不再保证每三次固定触发一次。
- 制作和微光拆解的总量、配方组选择及堆叠拆分与原版一致。
- 幸运只改变原版允许改变的概率和结果质量，不改变后续无关事件。

### 阶段 5：世界转阶段结果

| 功能 | 原版入口 | 确定性策略 |
| --- | --- | --- |
| 困难模式 V 位置 | `WorldGen.initializeHardMode` | 独立后台线程域；固定两条 V 的起点、方向和 runner 随机序列 |
| 困难模式矿物类型 | `WorldGen.SmashAltar` / `SavedOreTiers` | 每个矿物层级独立选择，保留醉酒世界切换规则 |
| 困难模式矿脉位置 | `WorldGen.SmashAltar` / `OreRunner` | 祭坛序号、矿物层级和矿脉序号组成事件键 |
| 月柱位置与类型顺序 | `WorldGen.TriggerLunarApocalypse` | 月球事件次数；保留五等分区域、地形和视线合法性检查 |
| 首个世纪之花球茎 | `GeneratePlanteraBulbOnAllMechsDefeated` | Race 开始前从神庙门上方 0–200、下方 100–200 格区域确定一个合法点；中/大世界按宽度缩放，且排除 `worldSurface` 以上位置 |

困难模式 V 和矿物不能使用跨线程全局 RNG 替换。受控随机调用必须走线程局部 provider；主线程刷怪、UI 和特效继续使用原版 `Main.rand`。

验收：

- 在同一世界文件的两份副本上执行转阶段，V 影响 tile 集合哈希一致。
- 相同祭坛序列产生相同矿物层级和矿簇坐标；敲击其他 tile 不影响结果。
- 月柱 NPC 类型及坐标一致；玩家改变地形后只允许合法位置搜索产生差异。
- 三机械 Boss 后先在预定点按正常规则生成；失败时依次检查该点半径 40 格内的原始合法候选，仍失败则按确定性顺序对全部原始候选使用 Terraria 自带的 `forceBulb` 规则。
- `forceBulb` 仍保留原版的受保护物件和周围丛林方块检查；玩家彻底破坏目标区域时允许生成失败。

### 阶段 6：星尘柱、城镇 NPC 检查和自然事件限制

工作：

- 普通 `NPC.SpawnNPC` 的 `spawnRate`、环境倍率和概率门全部保持原版，不安装刷怪率累加器。
- 星尘柱敌怪选择使用独立顺序域，覆盖区域刷怪选择及 `SpawnStardustMark_*` 派生敌怪。
- 进入指定 Race 世界时将 `Main.checkForSpawns` 归零；首次及后续城镇 NPC 检查都使用固定 1800 个游戏更新 tick 的周期，正常 60 Hz 下为 30 秒。
- 城镇 NPC 检查周期不再除以 `worldUpdateRate`，睡觉或时间加速不改变实际等待时间。
- 商人、护士、爆破专家等入住条件、房屋要求和原版优先级保持不变；检查中确实存在的随机候选分支使用独立确定性随机域。
- 旅行商的出现概率、时间和商品完全保持原版，不进入 Race 控制范围。
- 禁止自然 Boss、哥布林/海盗入侵、血月、日食、降雨、史莱姆雨和派对自然触发；召唤物、血泪、日曜碑牌、哥布林战旗和派对中心等玩家主动触发方式仍然允许。

验收：

- 普通区域和四柱区域的刷怪时间分布与原版一致；水蜡烛、和平蜡烛、战斗药水、城镇 NPC 数量和环境倍率继续生效。
- 星尘柱敌怪类型序列可复现，但不会改变敌怪出现时间。
- 两个客户端进入 Race 世界后首次及后续城镇 NPC 检查均相隔 1800 个游戏更新 tick，不受 `worldUpdateRate` 影响。
- 相同住房和解锁状态产生相同的城镇 NPC 候选；玩家条件不同允许产生不同结果。
- 旅行商行为与未安装 Hook 的原版客户端一致。
- 所列自然事件不会自行开始；对应玩家主动触发方式仍可正常启动。

### 阶段 7：保留原版方块更新

工作：

- 不 Hook `WorldGen.UpdateWorld` 的随机方块坐标选择。
- 草药、藤蔓、植被、移动对象和其他自然方块更新全部保持原版随机行为。
- 不要求不同客户端检查相同坐标，动态世界状态允许自然分歧。
- 本文将这些随机调用点明确记录为“保留原版”，避免以后误纳入受控域；运行时兼容性清单只记录实际 Hook 的方法。

验收：

- 世界更新路径不存在 TerrariaSplit 的每 tick Hook、托管分配或 IPC。
- 草药和植被等行为与未安装 Hook 的原版客户端一致，不以跨客户端结果相同作为验收条件。

### 阶段 8：覆盖审计与发布

工作：

- 用 IL 扫描生成所有 `Main.rand`、`WorldGen.genRand`、`Luck.Roll*` 调用点清单，逐项标记为受控、原版保留或纯视觉。
- 增加成对实机回放工具，输出域、事件键、计数器、累加器和结果摘要；普通日志只记录握手与失败，不逐 tick 写日志。
- 为每个能力增加独立开关以便开发期回归；正式 Race 配置只发布经过整体验收的能力集合。
- 发布前验证原生 DLL、net40 载荷、Harmony、许可证、SHA-256 和更新清单。
- 更新 Terraria 版本时重新生成方法清单和 IL 指纹，完整重跑成对回放后才加入支持列表。

验收：

- 两个客户端完成一条端到端 Race 流程，受控结果摘要一致。
- 在一端插入无关操作，只有语义上依赖该操作的域允许分歧。
- Hook 中断、版本错误、IPC 断开和载荷缺失都阻止 Ready。
- 完整测试、Release 构建和便携发布验证通过。

## 测试策略

- 纯模型：HMAC 派生、事件键、计数器、无偏独立概率掷骰、整数累加器和分母变化的 golden vectors。
- 兼容性：离线校验 exe、MVID、签名、方法 token 和 IL SHA-256。
- Hook 生命周期：安装、嵌套、异常恢复、卸载、进程退出和 IPC 断开。
- 成对回放：两个独立 Terraria 进程使用同一世界副本和随机包执行同一操作脚本。
- 隔离性：一端插入不相关的掉落、开包、特效或移动操作，验证其他域不漂移。
- 原版规则：比较幸运、普通刷怪倍率、城镇 NPC 入住条件、配方条件和前缀合法性，不只比较最终结果。
- 周期与事件：验证城镇 NPC 检查固定为 1800 个游戏更新 tick，并分别验证自然触发被拒绝、玩家主动触发仍可用。
- 性能：确认普通刷怪和方块更新路径没有新增高频 Hook、分配或 IPC。
- 失败关闭：载荷缺失、版本不匹配、方法指纹变化、重复注入和部分能力失败。
- 流程守卫：换世界、Host & Play、Join Game 以及通关后解除限制。

每个阶段必须先通过纯模型和离线兼容测试，再运行无副作用 Hook 验证，最后运行成对实机流程。不得用一个大范围 `Main.rand` 替换来伪造覆盖率。
