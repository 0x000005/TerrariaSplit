# Terraria 集成说明

## 职责
- 这里是对 Terraria 外部程序的适配层：进程查找、内存读取、窗口探测、菜单坐标、存档准备和自动化流程。
- 这里应把外部世界的不稳定细节转换成项目内稳定模型，再交给 Application 或 Domain 使用。
- `Memory/` 负责读取和解释 Terraria 进程状态，`Automation/` 负责编排点击和存档操作，`WorldGeneration/` 负责金字塔预筛和世界生成局部复刻。

## 设计原则
- 进程、内存和窗口读取都要容忍失败；普通外部失败应转成诊断或空状态，而不是让应用崩溃。
- 自动化流程应保持步骤清晰、可取消、可记录；应用层决定是否启动，集成层负责如何执行。
- 参考 Terraria 源码时，只提取必要字段、流程和状态含义；世界生成复刻只能在 `WorldGeneration/Simulation/` 内按需保留必要官方机制。
- 菜单几何、世界生成和存档处理应优先复用现有抽象，避免把坐标和文件规则散落到多个调用点。
- 不要让这里依赖 overlay 渲染或主窗体实现。
- 自动化可以调用金字塔预筛结果，但创建后 `.wld` 二验仍是兜底，不要把预筛当成唯一真相来源。

## 验证
- 修改内存地址、世界生成解析、菜单几何或自动化流程后，运行 `dotnet run --project test\TerrariaSplit.Tests.csproj`。
- 修改金字塔预筛链路时，优先跑 `TERRARIA_SPLIT_TEST_FILTER='Pyramid seed pre-screen'` 的聚焦测试，再按风险补跑数据集评估。
- 无法用自动测试覆盖的外部行为，在最终回复说明需要人工验证的具体场景。
